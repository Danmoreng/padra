Q8_0 MTP verification batching — 2026-10-25

Base: e61f329 (encoded prefix reuse already enabled). RTX 5080 Laptop, SM120a.
Build: Release; exact-fusions-v1, global-matrix-v1, async64-v1, packed-chunk-v1.
Target: stored shared Q8 head, EXL3 K3/K6 experts. Draft: pinned EXL3 K4 experts.
Q8_0 KV, 131072 capacity, chunk256, MTP D1. Admission ceilings: 8 GiB K3 / 12 GiB K6.
These ceilings on a 16 GB GPU do not qualify physical 8/12 GB cards.

Change: batch query encoding, DP4A attention, merge and FP8 encoding for two-row
verification. Each row retains the ordinary partition, DP4A accumulation, softmax
and rotation order. FP8 encoding uses the existing exact reciprocal implementation
with division at rounding boundaries. The overwritten local ring row comes from
its encoded rollback snapshot. Existing dead QKV/logit/gate arenas provide scratch.
No new resident buffer, cache shadow, head copy, weight format or numerical profile.
Plain Q8 and larger verification groups retain their sequential attention path.

Paired timing: six AB/BA process pairs per profile. Each process has one unretained
warm-up and one retained request. Natural 4096-token coding input, 512 generated
outputs. Decode rate=decode_steps/decode_s, including draft, verification, selection
and state repair; prefill and model initialization are separate. Actual output IDs,
final logit/hidden hashes, callbacks, state, proposals and acceptance match in all
48 requests. Telemetry and per-request results are retained.

- 90 additional unaligned-prefix cases across D0/D1/D4 remain exact.
- 30 attention operator cases at local/global positions 0 through 131070 plus 60 graph

- Memcheck, synccheck and initcheck pass the full operator set with zero errors.
 Full racecheck exceeded its 150-second time bound; no completed result is claimed.
 A dedicated subset of 6 cases and 12 replays covers tile/ring transitions and repeated async

Quality scope: this is an execution change, not a new quantization. Exactness is
checked against the same selected Q8_0 target. Existing Q8-head/KV quality caveats
relative to BF16 remain unchanged. Operator tests cover 131K attention positions;
these throughput measurements use 4K actual prompts with 131K allocated capacity.

Baseline profile evidence: 32 generated tokens, CUDA graph node trace. This is
for attribution, not the throughput benchmark. Q8 attention/encoding previously
ran separately per verifier row; batching removes four launches per layer/group
and replaces narrow output encoding with the existing wide exact implementation.
The 32-output trace has 12043 baseline versus 10251 candidate kernel launches;
Q8 query/split/merge launches decrease 2772->1428; narrow FP8 encoding 924->28,
with 448 wide batched encodings instead. Target experts remain the largest category.
