SM61 native K3 DP4A Prefill, 2026-10-25

The optional PADRA_PASCAL_DP4A_PREFILL=ON profile supports native K3 and K4.
K3 reads its packed 24-bit lane windows without expanding resident weights.
Dense expert projections quantize decoded weights and transformed H128
activation blocks to INT8, use DP4A, and retain the existing FP32 block combine
and BF16 output boundary. Sparse tails and ordinary/MTP Decode retain the exact
codec and FP32 arithmetic. The stored shared Q8 head is unchanged.

The compute profile is approximate, disabled by default, and explicitly named
mellum16-pascal-q8_0-dp4a-v2 in the Q8_0 runtime identity. It also uses the
existing 1024/4096/8192 bounded Prefill attention graphs at context 8192.
K3 and K4 dense kernels use 80 registers and 14784 shared bytes with no spills.

GTX 1070 Max-Q, 8 GiB, native K3, shared Q8 head, EXL3-K4 MTP D1, Q8_0 target
KV, context 8192, chunk 256. Three warm HTTP runs per length, 1000 output tokens,
no prompt-cache hits. Prefill includes first selection; Decode counts 999 steps.

Prefill latency is 4.012 / 7.946 seconds, about 70% more throughput than the
previous profile. The baseline is the earlier same-day repeated measurement,
not an interleaved paired experiment. Decode arithmetic is unchanged; no
independent Decode kernel speedup is attributed to this change. Outputs can
differ from the previous profile because Prefill arithmetic changes.
Peak observed system-wide VRAM is 5999 MiB, including the enabled prefix
snapshot allocation. Weights, tokenizer and target KV format are unchanged.

Validation:

- 26 real-model requests preserve exact ordinary/MTP and restore/fresh results

Reproduction: configure the SM61/SIMT release build with
-DPADRA_PASCAL_DP4A_PREFILL=ON and -DPADRA_BUILD_TESTS=ON, then build and run CTest.

  build/sm61-k3-dp4a/padra-pascal-dp4a-test --sanitize --k3
